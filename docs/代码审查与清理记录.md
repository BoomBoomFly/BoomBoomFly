## 当前实际主链路

```text
D435i → RealSense SDK/ROS wrapper → 图像 + IMU（已有采集记录）
                                ↓
                     OpenVINS / 标定 / 输出适配：未接入
                                ↓
/vision/odometry [nav_msgs/msg/Odometry, odom ENU / base_link FLU]
  → px4_vision_bridge DDS backend
  → px4_msgs/msg/VehicleOdometry
  → /fmu/in/vehicle_visual_odometry
  → Micro XRCE-DDS → PX4 vehicle_visual_odometry → EKF2（真实动态融合待验证）
```

仓库没有 OpenVINS 源码、manifest、launch 或实际 D435i 相机—IMU/机体标定配置。
不能将其 IMU 原点位姿直接改名为 base_link，也不能假定任意 VIO 世界朝向已经是 ENU；
接入时须处理朝向、平移杠杆臂、速度参考点、姿态误差协方差和 reset。当前 hardware reset
启发式默认关闭，没有真实估计器 reset 信号闭环。

DDS 接口核对：位置 NED；四元数是 FRD→NED，输出顺序 w,x,y,z；速度和角速度均为 BODY_FRD。
ROS Odometry 的 twist 必须在 child FLU 系，桥内不额外推断或转换上游 IMU 原点。
ROS 侧输入、timesync 和视觉输出使用 best-effort、volatile、有限 history；PX4 topic 类型/版本匹配。
本地 `uxrce_dds_client/utilities.hpp` 的 PX4 writer 为 best-effort/transient-local，reader 为
best-effort/volatile，与这些 ROS 订阅/发布 QoS 兼容。
PX4 的 `Tools/msg/templates/ucdr/msg.h.em` 对 timestamp/sample 序列化加 offset、反序列化减 offset；
bridge 使用该 DDS 边界域，保留 ROS 样本年龄。EKF2 的外部视觉融合参数和实际延迟仍需现场验证。

Offboard 实际链路为 H coordinator → navigation `ExecuteFlight` adapter → 唯一
`offboard_gateway_node` → `OffboardControlMode` / `TrajectorySetpoint` / `VehicleCommand`。
20 Hz position-only setpoint，未控制的速度、加速度、jerk、yawspeed 为 NaN；程序不发 ARM/DISARM。
状态订阅为 `/fmu/out/vehicle_status_v1`；进入 Offboard 必须同时有匹配 ACK 与实际模式状态。
单写入方已在源码/launch 层检查，现场重复启动进程仍须通过 ROS 图确认。

坐标语义依据：[ROS PoseWithCovariance](https://docs.ros.org/en/melodic/api/geometry_msgs/html/msg/PoseWithCovariance.html)
及本地 PX4 `EKF2.cpp` 中 `getRotVarBody()`、外部视觉输入处理；
[PX4 VehicleOdometry 定义](https://docs.px4.io/main/uk/msg_docs/VehicleOdometry)也明确姿态误差在机体系。
实现和消息版本以本地锁定源码为准。

## 保留项及原因

- 上游 PX4、Agent、RealSense 内的例程/测试：属于精确锁定的第三方仓库，不凭名称裁剪 SDK/固件。
- MAVROS：当前 launch、代码、测试与历史验证明确引用，属于仍可选择的 PX4 兼容后端；不在默认 DDS 主链路。
- `offboard_cpp/hardware/hardware.pdf`：旧 OrangePi 描述与 Jetson 不一致，但被架构文档引用，装机历史价值未确认，不强删。
- common 的 C99 core、公共消息，以及 communication、embedded_systems：已有契约、测试、manifest 或任务引用，未据“当前没有运行节点”推断无用。
- D FSM、H 覆盖规划、perception 初始说明：属于 Mission/规划/感知范围。D 尚无运行节点，真实感知尚无实现；H 网格仍假定场地与 NED 对齐，未完成现场标定。
- RealSense/PX4 消息的 build/install：现有 symlink-install 的共享库实际指向 build 路径，且 SDK 安装库包含本日已验证的 RSUSB 修复；删除会破坏相机调试环境。保留这些有效依赖，构建回归使用隔离目录。
- 未添加新 SLAM、规划框架、设备驱动或大规模容错机制；缺失能力需依据实际标定与任务数据实现。
