# BoomBoomFly 第一阶段实机门禁清单

本清单不授权解锁、起飞或修改 PX4 参数。每项均由现场操作员单独确认；任一失败均回到上一层排查。
Humble SITL 或代码测试不能代替本清单中的任何现场批准。

## 0. 软件与配置

- 记录根仓库和各嵌套仓库的 HEAD、工作区状态、PX4/px4_msgs/Agent 版本及生效参数。
- 确认唯一生产 writer：mission 写三个控制输入；vision bridge 只写
  `/fmu/in/vehicle_visual_odometry`。
- 确认硬件 `vision_bridge.yaml` 的输入 frame、机体 frame、VIO 外参和时钟来源均已实测。
- 启动 PX4 后确认 `/fmu/out/timesync_status` 新鲜；缺失或过期时 bridge 必须停止发布。

## 1. 无桨地面联调

- 由操作员启动 PX4、DDS Agent 与 `ros2 launch px4_bringup hardware.launch.py`；launch 不会自动解锁。
- 确认 mission 依次停在 `WAIT_DISARMED`、`WAIT_LOCALIZATION` 和 `READY`，且只在定位有效时进入 READY。
- 用 RC 验证 Kill、人工模式切换与 Offboard 退出；程序不得重新请求 Offboard。
- 验证只有 `STICK_GESTURE` 或 `RC_SWITCH` 的解锁上升沿可启动任务，且程序不发布 ARM/DISARM/Kill。

## 2. 定位与失效演练

- 手持相机完成单轴位移、旋转、静止和延迟检查，确认 EKF2 `VehicleLocalPosition` 方向与有效性正确。
- 注入 VIO 停止、过期时间戳、坏四元数和 timesync 中断；bridge 应停止写入，且在命令通路可用时 mission
  应请求原地 Land。
- 在无桨状态验证本地位置 reset 会按 PX4 delta 修正冻结的 home 和活动目标。
- 若验证取消服务：仅 HOVER 可接受；RC 接管、failsafe 和定位失效必须优先于取消。

## 3. 受控飞行

- 仅在定位、Kill、人工接管和 Offboard-loss 演练全部通过后，进入系留或保护场地。
- 按顺序验证：1.5 m 起飞、稳定判据、60 s 悬停、本地 home 返回、PX4 Land、操作员解除解锁。
- 保存 mission state/event/fault、`VehicleStatus`、`VehicleLocalPosition`、`VehicleOdometry`、
  `VehicleCommandAck` 和 PX4 ulog；记录异常时间点。
