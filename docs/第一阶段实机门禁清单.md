# BoomBoomFly 第一阶段实机门禁清单

本清单不授权解锁、起飞、修改 PX4 参数或绕过现场流程。每一阶段都由现场操作员单独确认；任一失败均
停止并回到上一层。离线测试、Humble SITL 和 legacy 飞行证据都不能替代目标硬件批准。

## 0. 可复现基线

- 顶层与所有嵌套仓库必须干净，`verify_repos.py` 通过；记录 manifest、HEAD、远端、PX4、`px4_msgs`
  和 Agent 的精确版本。
- 目标机固定为 Jetson Orin Nano、Ubuntu 22.04、ROS 2 Humble；记录实际发行版、ROS 2 patch、RMW、内核
  和关键系统依赖，不能只以开发机 Humble 构建结果替代目标机验证。
- 新架构使用 `start_gateway=true start_mission=false`。legacy 回放只能反向选择，两者不得同时启动。
- 启动后确认三个 PX4 控制输入各只有一个 `offboard_cpp` writer；TI、感知和设备节点均不得发布
  `/fmu/in/*`。
- 确认 Action、状态、观测和设备接口来自同一 `boomboom_common` 版本。
- 确认所有目标硬件参数已记录；不得把 SITL 中临时修改的 `COM_OF_LOSS_T=0` 带到实机。

## 1. 无桨地面联调

- 由操作员启动 PX4、DDS Agent 和 `px4_bringup hardware.launch.py`；launch 不会自动 ARM。
- 确认 `/fmu/out/vehicle_status_v1`、本地位置、landed、ACK 和 `TimesyncStatus` 新鲜，
  `/boomboom/flight_state` 的 armed/offboard/localization/failsafe 与 PX4 一致。
- 确认只有观察过 `DISARMED`、本地位置与 heading 健康并出现 RC 解锁上升沿后，`TAKEOFF` 才能推进；
  程序始终不发送 ARM、DISARM 或 Kill。
- 用 RC 验证 Kill、人工模式切换、Offboard 退出和 failsafe；gateway 不得重新抢权。
- 验证非 Land 动作取消后保持当前位置；Land 一旦请求不可取消，并且只接受请求后的新 landed 样本。

## 2. 定位、视觉与时间

- 用已标定输入完成单轴位移、旋转、静止、延迟和 reset 检查，确认 EKF2 NED 位置与 yaw 方向正确。
- DDS 模式只允许 bridge 写 `/fmu/in/vehicle_visual_odometry`；输入或 timesync 失效时必须停止发布。
- MAVROS 模式必须提供已标定的 `odom_frame -> base_link` TF，保持
  `source_frame_id=base_link` 和 `require_body_source_frame=true`；不得把 `camera_link` pose 当机体 pose。
- DDS 与 MAVROS 视觉输入不得并发；MAVROS 模式还必须检查 FCU 连接、唯一 PoseStamped publisher 和
  PX4 侧唯一视觉估计链。
- 在目标 Jetson 上监视 realtime、monotonic 和 boottime；不得把 WSL 的临时 timesyncd 处理结论直接
  外推到 Jetson。
- 注入 VIO 停止、过期时间戳、坏四元数、heading 无效和 timesync 中断；在命令通路可用时 gateway 应
  请求原地 Land，不盲目返航。

## 3. TI 与设备台架

- `px4_bringup/config/ti` 中的任务配置保持 `auto_start=false`；统一入口为
  `px4_bringup/launch/ti_task.launch.py`。外部 START 只能请求任务，不能 ARM 或绕过 gateway。
- H/D 任务分别验证，互不启动或依赖；所有飞行动作只经 `boomboom_navigation` 调用 Action。
- 感知输入只改变任务观测，不直接产生飞控 setpoint。
- 激光器和投放器必须在独立台架验证 sequence、幂等、超时、ABORT 和回执；装机前不得启用真实负载。
- 动物/小车跟踪、动态降落或投放任一任务链未完成模拟和 SITL 时，不得进入对应实机项目。

## 4. 受控飞行

- 新 gateway 必须先在相同配置的 SITL 通过 RC 启动、Action 顺序、取消、定位失效、人工接管、
  Offboard-loss 和 Land 新样本门禁。
- 只有定位、Kill、人工接管、Offboard-loss、通信中断和节点退出的无桨演练全部通过，才可由操作员决定
  是否进入系留或保护场地。
- 先验证 gateway 最小链路：`TAKEOFF -> HOLD -> RETURN_HOME -> LAND`；不得直接以 H/D 完整任务作为首飞。
- 保存 `FlightState`、Action goal/feedback/result、PX4 状态、本地位置、视觉里程计、command/ACK、landed
  和 PX4 ULog，并记录配置、操作员确认与异常时间点。
- 最小链路通过后，H/D 任务仍须分别重新走本清单；一次成功不能互相替代。
