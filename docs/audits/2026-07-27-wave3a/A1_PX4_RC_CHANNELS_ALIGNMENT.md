## 5. Minimum `rc_channels` firmware-profile diff design

After an approved exact PX4 source lock exists, the intended conceptual change
is one new PX4-to-ROS publication in the locked v1.16.2
`dds_topics.yaml`:

```diff
 publications:
+  - topic: /fmu/out/rc_channels
+    type: px4_msgs::msg::RcChannels
```

This is a design sketch, not an apply-ready patch. The exact path, YAML keys,
ordering, message-version behavior, and generated symbol names must first be
read from the locked PX4 source. The minimum patch must satisfy all of these
constraints:

1. add only the `RcChannels` output publication needed by the RC safety
   interlock;
2. make no PX4 uORB message-field change if the locked source definition
   already matches the message contract;
3. add no PX4 input subscription and no unrelated output;
4. preserve the frozen baseline topic set;
5. specifically do **not** add `/fmu/in/landing_target_pose` or any other
   precision-landing endpoint;
6. produce exactly one PX4 `/fmu/out/rc_channels` DataWriter with the frozen
   type and compatible QoS;
7. fail generation or validation if the message fields, endpoint name, type,
   QoS, or source identity differ.

Precision landing remains a separate optional profile. Its
`enable_precland=false` default and its absence from the baseline must be
tested independently; a future optional profile cannot silently change this
baseline.
